# ADR-009: 포즈 파일을 클립스튜디오로 전달하는 방식

- 상태: 제안됨
- 날짜: 2026-07-30
- 관련 문서: docs/12_EXPORT_AND_SAVE_SPEC.md, docs/03_USER_FLOW_AND_SCREENS.md §8·§8-1·§9, docs/adr/ADR-006-bvh-download.md, docs/adr/ADR-008-window-modes.md

## 배경

후보를 고른 뒤 그 포즈가 실제로 클립스튜디오(이하 CSP) 캔버스에 들어가기까지의 동작이 너무 많다. ADR-006 시점의 흐름을 세면 저장 화면 진입 → 폴더 확인 → 파일 이름 확인 → 저장 버튼 → 폴더 열기 → 탐색기에서 파일 찾기까지 앱 쪽에서만 여섯 단계가 걸리고, 그 뒤에 CSP 쪽 동작이 다시 붙는다.

원래 구상한 최종 목표는 "CSP 소재(에셋) 폴더에 자동 저장"이었다. 이 목표가 성립하는지 조사한 결과와 근거는 `docs/12_EXPORT_AND_SAVE_SPEC.md` §5에 정리했다. 결론은 성립하지 않는다.

대신 팀원 검증으로 확인된 사실이 있다.

- **BVH 파일을 탐색기에서 CSP 캔버스로 드래그하면 3D 데생 인형이 자동으로 생성되고 포즈가 적용된다.** 캔버스에 인형을 미리 놓거나 선택해둘 필요가 없다.
- 검증 범위는 **탐색기(폴더) → CSP 캔버스** 드래그다. 앱 창에서 CSP로 직접 드래그하는 경로는 아직 검증되지 않았다.

즉 사용자가 CSP에서 해야 하는 동작은 이미 드래그 한 번으로 줄일 수 있다. 남은 마찰은 대부분 앱 쪽이고, 그건 우리가 없앨 수 있다.

## 선택지

- **A. 소재 폴더에 직접 파일 저장.** 경로가 사용자 설정값이라 탐지가 필요하고, 파일을 넣어도 소재 팔레트가 인식하지 않는다. 인식은 소재 DB 등록 기준이며 수동 복사 후에는 사용자가 CLIP STUDIO 앱에서 "소재 데이터베이스 재구성"을 실행해야 한다. 그리고 BVH는 애초에 소재 타입이 아니다.
- **B. 소재 DB에 직접 등재.** 원리적으로는 가능하지만 미공개 포맷 세 겹(청크 컨테이너, 소재 카탈로그 스키마, 포즈 페이로드)을 해석해야 하고, CSP가 소재 쓰기에 프로세스 간 락을 사용해 CSP 종료가 전제된다. EULA의 제품 분석·리버스 엔지니어링 금지에 저촉되며, 실패 시 사용자의 소재 라이브러리 전체가 손상된다.
- **C. CSP 메뉴 임포트 최적화.** 저장 폴더를 고정하고 파일 이름을 고정해 `파일 > 가져오기 > 3D 데이터`에 할당한 단축키 → Enter → Enter로 줄인다. EULA 안에서 안전하고 구버전에서도 동작하지만 하한이 세 번의 키 입력이다.
- **D. 드래그 앤 드롭 우선 + 고정 폴더 자동 저장.** 후보를 고르면 설정된 저장 폴더에 대화상자 없이 바로 저장하고, 사용자는 그 폴더에서 CSP 캔버스로 드래그한다. 검증된 경로다.
- **E. 앱에서 CSP로 직접 네이티브 드래그.** `tauri-plugin-drag`로 후보 카드 자체를 드래그 소스로 만든다. 성공하면 폴더를 경유하지 않아 동작이 하나로 줄지만, 아직 검증되지 않았다.

## 결정

**D를 기반으로 하고 E를 주 경로로 올린다.** D(폴더 열기 → 탐색기에서 드래그)와 C는 폴백으로 남긴다. A와 B는 영구 제외한다.

근거:

- 저장 대화상자를 없애는 것이 가장 큰 이득이다. 마찰의 대부분은 CSP 임포트가 아니라 앱 쪽 저장 단계에 있었다. D와 E 모두 이 이득을 가져간다.
- E는 D에서 탐색기 경유를 더 없앤다. 저장이 자동으로 선행되므로 파일이 이미 디스크에 있고, 드래그 소스로 만드는 데 추가 조건이 없다. 특히 바 모드는 CSP 위에 떠 있어 드래그 거리가 가장 짧다.
- E의 위험은 D를 폴백으로 유지하면 흡수된다. 드래그가 실패하거나 브라우저 개발 모드처럼 지원되지 않는 환경에서는 `폴더 열기`로 검증된 경로를 그대로 쓴다.
- A·B는 기술적 실현성과 법적 안전성이 모두 부족하다. 특히 B의 최악 손실(사용자 소재 라이브러리 손상)은 기대 이득(동작 몇 번 절약)과 비대칭적으로 크다.
- C는 안전하지만 사용자가 CSP에서 단축키를 직접 등록해야 하고 하한이 D보다 높다. 드래그가 막힌 환경의 폴백으로는 유효하다.

## 결과

- 저장은 **설정된 저장 폴더에 자동 저장**한다. 저장 버튼을 반복해서 누르는 단계를 없앤다.
- 저장 폴더는 **설정 화면에서 변경**한다(`docs/03` §9). 기본값은 OS 다운로드 폴더다.
- 저장 결과에는 **"다른 폴더에 저장"** 부가 버튼을 둔다. 이번 한 번만 다른 위치에 저장하는 용도이며, 설정의 기본 폴더를 바꾸지는 않는다.
- 저장 결과 목록의 **각 행이 드래그 소스**다(`tauri-plugin-drag`). 파일은 항상 **복사 모드**로 넘겨 원본이 저장 폴더에 남게 한다(`CLAUDE.md` §5 비파괴적 흐름).
- 드롭 결과는 **사용자가 놓았다는 사실까지만** 표시하고 확인을 사용자에게 넘긴다. 플러그인의 `Dropped`는 OS 드래그 세션 종료 신호일 뿐 CSP의 수용 여부와 무관하므로 "전달됨"도 과한 단정이다(`CLAUDE.md` §10).
- 폴백 셋을 유지한다: **"폴더 열기"**(탐색기에서 드래그, 검증된 경로), **"경로 복사"**(CSP 임포트 대화상자 붙여넣기), CSP 메뉴 단축키 안내.
- 브라우저 개발 모드는 OS 드래그를 시작할 수 없다. `dragService.isSupported`로 어피던스를 감추고 안내 문구를 폴더 열기 기준으로 바꾼다.
- 영구 제외: 소재 폴더 직접 저장, 소재 DB 조작, CSP GUI 키스트로크 자동화. 사유는 `docs/12` §6.
- 전제: BVH 임포트는 CSP Ver 3.1 이상이 필요하다. 그 이하 버전 사용자는 이번 결정으로 커버되지 않으며 FBX 확장 시 재검토한다(`docs/12` §7).
- 감수하는 트레이드오프: BVH의 캔버스 드롭은 공식 문서의 드롭 지원 포맷 목록에 없는 동작이다. 실측으로는 동작하지만 문서화되지 않은 경로이므로 CSP 버전업에서 바뀔 수 있다. 그래서 폴백을 셋 다 유지한다.
- **검증 완료(2026-07-31).** 임시 하네스(`/dev/drag-test`)로 확인한 뒤 하네스는 제거했다.
  - 앱 창 → CSP 드래그를 CSP가 **파일 드롭으로 받는다**(PNG·OBJ로 먼저 확인).
  - **BVH도 동작한다.** 이 결정의 주 경로가 성립한다.
  - 드래그 후 **원본이 저장 폴더에 남는다**(`mode: "copy"` 확인).
  - 검증 도중 얻은 것: BVH 파일이 유효하지 않으면 CSP가 "모션 파일 가져오기에 실패했습니다"로 거절한다. 전달 경로와 별개로 서버가 생성하는 BVH의 조인트 구조가 요건을 만족해야 한다.
- 재검토 조건:
  - CSP 버전업으로 BVH 드롭이 막히면 주 경로를 D(폴더 열기 → 탐색기 드래그)로 되돌린다. 드래그 어피던스만 감추면 되므로 되돌리기 비용은 작다.
  - 후보 카드에서 바로 드래그하려면 사전 스테이징이 필요하다(`docs/12` §7).
  - FBX 출력이 추가되면 포맷별 전달 경로를 다시 정리한다.
  - CSP 버전업으로 BVH 드롭이 막히면 C를 주 경로로 승격한다.
