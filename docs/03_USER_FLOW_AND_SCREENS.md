# 사용자 흐름 및 화면 명세

## 1. 전체 흐름

```text
앱 실행
├─ 세션 있음 → 홈
└─ 세션 없음 → 로그인
                  │
                  ▼
                 홈
        ┌─────────┴─────────┐
        ▼                   ▼
      파일                 캡처
      업로드               시작
        └─────────┬─────────┘
                  ▼
              입력 미리보기
                  ▼
               분석 요청
                  ▼
              분석 진행 화면
                  ▼
             포즈 후보 뷰어
            ┌─────┴─────┐
            ▼           ▼
         후보 선택     다시 검색
            ▼
   설정된 폴더에 자동 저장
            ▼
      폴더 열기 → 클립스튜디오 캔버스로 드래그
```

### 첫 실행

데이터 수집 동의를 마치고(macOS는 화면 기록 권한 단계를 거쳐) 홈에 처음 도착하면 앱 사용법 투어가 저절로 시작된다. 투어는 실제 화면의 요소를 하나씩 강조하며, 설명 스텝은 '다음'으로, 동작 스텝은 **사용자가 실제로 그 버튼을 눌러야** 넘어간다. 위 흐름을 한 번 완주하는 것이 목표다.

- 스텝은 순번이 아니라 현재 라우트와 앱 상태에서 파생한다. 캡처를 취소하거나 '다시 선택'으로 돌아오면 그 화면의 스텝이 저절로 다시 활성이 된다.
- 캡처 오버레이와 플로팅 바에서는 투어를 그리지 않는다. 앱 모드로 돌아오면 이어진다.
- 분석 실패·저장 실패에는 투어를 마치는 안내 스텝이 따로 있다. 실패한 흐름을 성공한 것처럼 이어가지 않는다.
- 한 번 완주하거나 그만두면 다시 저절로 뜨지 않는다. 설정 > 앱 사용법과 상단 앱 바의 도움말 버튼으로 언제든 처음부터 다시 본다.

## 2. 로그인 화면

### 목적

앱 진입을 빠르게 완료한다.

### 구성

- Standin 로고
- 짧은 문구: `콘티에서 시작하는 3D 포즈 어시스턴트`
- 이메일
- 비밀번호
- 로그인 버튼
- 로그인 유지 안내
- 계정 만들기: 웹 링크
- 비밀번호 찾기: 웹 링크
- 서버 연결 오류 영역

### 상태

- 기본
- 입력 오류
- 로그인 중
- 인증 실패
- 네트워크 실패
- 서버 점검

### 금지

- 로그인 실패 사유를 너무 기술적으로 노출
- 존재하는 이메일인지 구분되는 상세 오류
- 버튼 연속 제출

## 4. 홈 화면

### 핵심 목표

앱을 켠 즉시 입력 방법을 선택하게 한다.

### 상단

Title:
`어떤 장면을 3D 포즈로 바꿔볼까요?`

Description:
`파일을 놓거나 화면에서 필요한 부분만 바로 캡처하세요.`

### 입력 카드

#### 파일 업로드

- 이미지 드래그 앤 드롭
- 파일 선택
- 지원 형식 표시
- 최근 파일

#### 화면 캡처

- 주요 CTA
- 단축키 표시
- `영역 캡처`
- 향후 `창 캡처`, `전체 화면`

#### 의견 보내기

- 랜딩 설문(`{webBaseUrl}/feedback/`)을 기본 브라우저로 연다
- 앱 상태는 바뀌지 않는다
- 앱에 없는 기능의 수요를 여기서 받는다

### 최근 작업

- 입력 썸네일
- 생성 시각
- 상태
- 다시 열기

이번 주에는 Mock 데이터 또는 빈 상태만 구현 가능하다.

## 5. 입력 미리보기 화면

### 구성

- 원본 이미지
- 파일 이름 또는 `화면 캡처`
- 이미지 크기
- 필요 시 크롭
- 회전
- 삭제
- 다시 캡처
- 분석 시작

### 다중 파일 정책

초기 MVP 권장:

- 한 번에 한 이미지 또는 한 컷
- 파일 선택은 여러 개 가능하게 열어두더라도 분석은 Job별로 분리
- 이번 주 UI는 단일 입력 우선

### 검증 오류

- 지원하지 않는 확장자
- 파일 크기 초과
- 손상된 파일
- 이미지가 너무 작음
- 캡처 취소

## 6. 분석 진행 화면

### 단계

1. `업로드 중`
2. `장면 확인 중`
3. `인물과 포즈 분석 중`
4. `가까운 포즈 검색 중`
5. `후보 준비 중`

실제 서버 단계와 매핑하되, 서버가 제공하지 않는 가짜 퍼센트는 만들지 않는다.

### 표시

- 단계형 progress
- 경과 시간
- 취소 가능 여부
- 백그라운드 이동
- 오류 시 다시 시도

### 긴 작업

앱 내 다른 화면으로 이동해도 작업 상태를 유지한다.

## 7. 포즈 후보 뷰어

### 목적

5개 후보를 빠르게 비교하고 하나를 선택한다.

### Desktop 레이아웃

```text
┌──────────────────────────────────────────────┐
│ 원본 / 분석 오버레이     선택 후보 큰 뷰어   │
│                                              │
├──────────────────────────────────────────────┤
│ 후보 1 │ 후보 2 │ 후보 3 │ 후보 4 │ 후보 5  │
├──────────────────────────────────────────────┤
│ 다시 검색                  이 포즈 사용하기   │
└──────────────────────────────────────────────┘
```

### 후보 카드

- 번호
- 썸네일
- 핵심 태그
- 선택 상태
- `보정 필요` 같은 안내
- 개발자 모드에서만 원시 점수

### 큰 뷰어

MVP 선택지:

1. 정적 다각도 렌더 이미지
2. 회전 가능한 GLB 마네킹
3. BVH를 기준 리그에 적용한 Three.js 뷰어

초기에는 서버가 렌더한 이미지가 가장 빠르고 안정적이다.

### 뷰어 조작

3D 도입 시:

- 회전
- 확대·축소
- 정면 복귀
- 원본 오버레이 켜기·끄기
- 관절 편집은 MVP 제외

### 다시 검색

버튼:
`다른 후보 찾기`

동작:
- 같은 입력과 분석 결과를 재사용
- 새로운 검색 Job 생성
- 기존 후보를 작업 기록에 보존할지 서버와 협의

## 8. 저장 화면 (ADR-009)

후보를 고르면 **설정된 저장 폴더에 대화상자 없이 바로 저장한다.** 저장 버튼을 눌러 경로를 확정하는 단계는 없다. 이 화면은 경로를 입력받는 곳이 아니라 저장 결과를 알리고 클립스튜디오로 넘기는 곳이다.

### 구성

- 선택한 포즈
- 파일 형식: BVH
- 저장된 파일 목록 — **각 행이 드래그 소스다.** 행을 클립스튜디오 캔버스로 끌어놓으면 끝
- `경로 복사` — 행마다. 클립스튜디오 임포트 대화상자에 붙여넣는 폴백
- `폴더 열기` — 폴백. 탐색기에서 직접 끌어놓는 경로
- `다른 폴더에 저장` — 부가. 이번 한 번만 다른 위치에 저장하며 설정의 기본 폴더는 바꾸지 않는다
- `새 장면 분석`

드래그는 항상 복사 모드다. 원본은 저장 폴더에 남는다. 드롭이 끝나면 그 행에 `반영됐는지 확인해 주세요`를 **보조 텍스트 색**으로 표시하고, 이유는 툴팁에 둔다.

기본 파일명:

```text
standin_pose_YYYYMMDD_HHmm.bvh
```

사용자가 원본 파일명을 제공했다면:

```text
{originalName}_standin_pose.bvh
```

### 안내 문구

파일 목록 위에 한 줄을 둔다. 네이티브 드래그를 지원하지 않는 환경(브라우저 개발 모드)에서는 폴더 열기 기준으로 바꾼다.

```text
아래 파일을 클립스튜디오 캔버스로 끌어놓으면 데생 인형이 만들어집니다.
폴더를 열어 BVH를 클립스튜디오 캔버스로 끌어놓으면 데생 인형이 만들어집니다.
```

클립스튜디오 안에서 실제로 적용됐는지는 앱이 알 수 없으므로 "포즈 적용 완료" 같은 단정은 하지 않는다(`CLAUDE.md` §10).

"전달됨"도 쓰지 않는다. 플러그인이 주는 드롭 결과는 **OS 드래그 세션이 끝났다**는 신호일 뿐 대상 앱이 파일을 받았는지와 무관하다. 작가 인터뷰에서 캔버스·레이어 어디에도 반영되지 않았는데 "전달됨"이 떠서 성공으로 읽혔다. 앱이 아는 사실(사용자가 놓았다)만 말하고 확인은 사용자에게 넘긴다. 성공색을 쓰지 않는 것도 같은 이유다.

### 상태

- 저장 중: 경로 영역에 로딩, 버튼 disabled
- 저장 완료: 완료 토스트 + 경로 표시
- 저장 실패: 인라인 오류. 폴더 권한 없음·폴더 삭제됨은 다운로드 폴더로 되돌리는 행동을 함께 제공한다
- 다중 인물: 인물별로 파일이 나뉘므로 파일 목록으로 보여주고 어느 인물인지 표시한다

저장 폴더 기본값과 변경 규칙, 클립스튜디오 전달 경로와 영구 제외 범위는 `docs/12_EXPORT_AND_SAVE_SPEC.md`를 따른다.

## 8-1. 플로팅 바 (ADR-008)

작가가 그림 작업 화면 위에서 **앱 창에 진입하지 않고** 캡처 → 후보 확인 → 저장까지 끝내는 경로다. 창 하나를 바 모드로 변형하므로 앱 화면과 동시에 보이지는 않는다.

진입 경로 세 가지: 전역 단축키(`Ctrl+Alt+S`), 앱 상단 바의 "플로팅 바" 버튼, **앱 창 최소화**. 최소화는 작업 표시줄로 숨는 대신 접힌 바로 전환된다(네이티브가 가로챈다).

이미 펼쳐져 있으면 단축키가 접는 토글로 동작하고, 흐름 도중(진행·후보·저장)에는 작업을 잃지 않도록 접지 않는다.

앱 창은 항상 무장식이라 제목 표시줄을 앱이 직접 그린다(ADR-008 실측 보정). 최소화·최대화·닫기 버튼은 그 표시줄에 있다.

| 상태 | 크기 | 내용 |
|---|---|---|
| 접힘 | 56×56 | 옮길 수 있는 원형 버튼. 기본 상태 |
| 동작 | 360×72 | 화면 캡처(`C`) · 파일 업로드(`U`) |
| 진행 | 360×96 | 분석 진행 상태 |
| 후보 | 720×460 | 후보 5개 비교·선택. 다중 인물은 스테퍼로 전환 |
| 저장 | 420×300 | 드래그 가능한 파일 목록 · 폴더 열기 · 다른 폴더에 저장 |

규칙:

- 바는 항상 위에 뜨고 테두리가 없다. 상단 핸들을 드래그해 옮기며 위치는 다음 실행에도 유지된다. 모니터 작업 영역 밖으로 나가지 않는다.
- 캡처 시 바를 숨긴 뒤 촬영하므로 결과물에 바가 찍히지 않는다.
- 앱 모드와 달리 **미리보기 단계를 건너뛰고** 바로 분석에 들어간다("적은 동작으로 캡처·선택").
- 후보를 앱이 자동 확정하지 않는 원칙은 바에서도 같다.
- 저장도 앱 모드와 같다. 후보를 고르면 설정된 폴더에 자동 저장되고, 바의 파일 목록에서 클립스튜디오 캔버스로 바로 끌어놓는다. 바가 클립스튜디오 위에 떠 있어 드래그 거리가 가장 짧다(ADR-009).
- 미인증 상태면 바를 열지 않고 앱 모드로 확장해 로그인 화면을 보여준다. 로그인 폼은 좁은 창에 들어갈 수 없다.
- 셸의 "앱 창으로 열기"로 언제든 앱 모드로 나갈 수 있다.

## 9. 설정 화면

MVP:

- 로그아웃 — **구현됨**
- 캡처 단축키 — **구현됨**
- 기본 저장 폴더 — **구현됨**
- 테마: 시스템 / 라이트 / 다크
- 서버 연결 정보는 개발 환경에서만
- 앱 버전

### 기본 저장 폴더 섹션

포즈 파일이 자동 저장될 폴더다. 저장 화면에서 매번 경로를 확인하지 않으므로 이 값을 바꾸는 곳은 여기 하나다(ADR-009).

- 현재 경로 · `변경` · `기본값으로` 버튼
- `변경`은 네이티브 폴더 선택 대화상자를 연다
- 폴더가 삭제되었거나 쓰기 권한이 없으면 인라인 경고를 표시하고 다운로드 폴더로 되돌리는 행동을 제공한다
- 저장 화면의 "다른 폴더에 저장"은 이번 한 번만 적용되며 이 값을 바꾸지 않는다

### 단축키 섹션

전역 캡처 단축키만 재지정할 수 있고 앱 내 단축키는 "고정"으로 표시한다(docs/07 §7).

- 각 행: 라벨 · 현재 키 · 변경/기본값 버튼
- 전역 행에는 등록 상태(등록됨 / 등록 중 / 등록 실패 / 데스크톱 전용)를 함께 표시
- 변경은 키 입력을 받는 대화상자에서 진행하고, 충돌 시 사유를 보여주며 저장을 막는다
- 등록 실패는 복구 행동이 필요하므로 Toast가 아니라 인라인 오류 + 되돌리기로 처리한다
- "단축키 전체 보기"로 치트시트를 연다

후속:

- 자동 업데이트
- 개인정보 및 데이터 보관
- 분석 기록 자동 삭제
- 포즈 뷰어 품질
