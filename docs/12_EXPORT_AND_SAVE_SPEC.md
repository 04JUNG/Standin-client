# 포즈 후보 뷰어 및 저장 위치 명세

## 1. 오늘 목표

- 포즈 후보 5개를 비교하고 마음에 드는 후보를 선택하는 뷰어 구현
- 저장 위치를 사용자가 선택할 수 있게 하되, 기본값은 다운로드 폴더로 지정
- 저장 버튼을 누르면 선택한 로컬 경로에 파일이 자동 저장

이번 목표는 클립스튜디오 소재 폴더에 직접 저장하는 기능을 포함하지 않는다. 관련 조사 내용은 §5~§7에 정리하고, MVP 범위는 §6에서 명확히 한다.

---

## 2. 포즈 후보 뷰어

`docs/01_PRODUCT_AND_MVP.md` §5의 후보 뷰어 요구사항을 따른다.

- 포즈 후보 5개를 나란히 표시
- 후보별 썸네일과 `matchLevel`(`high` / `medium` / `low`) 표시
- 카드 클릭 시 선택 상태로 전환, 선택된 카드는 확대 비교 가능
- 후보 선택은 서버 상태와 분리해 관리한다(`PoseSelectionState`, `docs/09_STATE_AND_DATA_MODEL.md` §4)
- 자동 확정 없음: 하나를 사용자가 직접 선택해야 다음 단계(저장)로 진행

타입은 `docs/09_STATE_AND_DATA_MODEL.md`의 `PoseCandidate`, `AnalysisResult`를 그대로 사용한다.

---

## 3. 저장 위치 선택 흐름

```text
후보 선택
→ 저장 화면 진입
→ 기본 저장 위치 표시(다운로드 폴더 또는 마지막으로 사용한 폴더)
→ 사용자가 필요 시 "다른 폴더 선택" → 네이티브 폴더 선택 대화상자
→ 저장 버튼
→ 로컬에 파일 저장(BVH)
→ 저장 완료 토스트 + "폴더 열기"
```

저장 위치 선택과 실제 파일 다운로드·쓰기는 ADR-006(`docs/adr/ADR-006-bvh-download.md`)의 결정을 따른다: Rust command에서 다운로드와 저장 대화상자, 파일 쓰기를 함께 처리한다(B1).

---

## 4. 기본 저장 폴더 규칙

- 최초 기본값: OS 표준 다운로드 폴더
  - Windows: `%USERPROFILE%\Downloads`
  - macOS: `~/Downloads`
  - Tauri의 경로 API로 조회하고 하드코딩하지 않는다.
- 사용자가 다른 폴더를 선택하면 그 경로를 preference로 저장하고, 다음 저장부터 기본값으로 사용한다(`docs/03_USER_FLOW_AND_SCREENS.md` §9 "기본 저장 폴더" 설정과 동일한 값).
- preference 저장 위치는 앱 데이터 디렉터리(`docs/09_STATE_AND_DATA_MODEL.md` §5 로컬 저장 방식과 동일한 원칙).
- 선택한 폴더에 쓰기 권한이 없거나 폴더가 삭제된 경우, 저장 시점에 오류를 표시하고 다운로드 폴더로 되돌아가는 옵션을 제공한다.

## 5. 클립스튜디오 소재 폴더 조사

목적: 향후 "클립스튜디오에서 바로 쓸 수 있는 위치에 저장"을 지원할지 판단하기 위한 사전 조사. 아래 경로는 설치 환경에 따라 달라질 수 있으므로 **하드코딩 금지, 반드시 실제 경로 탐지 로직 필요**.

### Windows

- 기본: `C:\Users\(사용자명)\Documents\CELSYS\CLIPStudioCommon\`
- 설치 환경에 따라 문서 폴더가 아니라 `C:\Users\(사용자명)\AppData\Roaming\CELSYSUserData\CELSYS`에 위치하는 경우도 있음
- 실제 경로 확인 방법: CLIP STUDIO(런처) → 톱니바퀴 → 메인터넌스 메뉴 → **"유저 데이터 폴더로 이동"** — 이 메뉴로 열리는 폴더가 실제 사용 중인 경로

### macOS

- 기본: `~/Documents/CELSYS/CLIPStudioCommon/`
- 단, 일본판 1.6 이상부터는 실제 데이터를 유저 Library 폴더로 옮기고 Documents에는 앨리어스(alias)만 남기는 케이스가 있음 → macOS는 Windows와 별도로 확인 필요

### 폴더 내부 구조와 제약

- 소재 실체는 `CLIPStudioCommon\Material\` 아래에 위치
- ASSETS에서 내려받은 소재는 **암호화된 임의 폴더 구조**로 저장되어, 다른 소프트웨어가 이 폴더에 파일을 직접 넣어도 클립스튜디오 소재 팔레트가 인식하지 못함(기존에 파악한 문제와 동일한 근거)
- 사용자는 CLIP STUDIO 설정의 "소재 저장 장소"에서 이 위치를 임의 경로로 변경할 수 있음 → 프로그래밍으로 다루려면 고정 경로 가정이 아니라 실제 경로를 탐지하는 로직이 필요

## 6. MVP 범위 결정

- 이번 목표에서는 클립스튜디오 소재 폴더에 직접 저장하는 기능을 구현하지 않는다.
- 이유: ASSETS 소재와 동일하게 암호화된 폴더 구조/소재 DB 등록이 인식 조건일 가능성이 높아, 단순히 파일을 폴더에 넣는 방식으로는 소재 팔레트에 노출되지 않을 것으로 예상됨(§7 스파이크로 검증 예정).
- 따라서 저장 대상은 사용자가 선택한 일반 파일 시스템 경로(기본값: 다운로드 폴더)로 한정한다.
- 클립스튜디오 폴더 자동 저장은 §7 스파이크 실험 결과가 나온 뒤 별도 ADR로 재검토한다.

---

## 7. 후속 스파이크 실험 계획(범위 밖, 참고용)

클립스튜디오 소재 팔레트 인식 조건을 확인하기 위한 실험 초안:

1. 클립스튜디오에서 소재를 수동으로 팔레트에 등록하기 전/후로 `CLIPStudioCommon\Material\` 폴더 스냅샷을 뜬다.
2. 같은 시점에 `CLIPStudioCommon` 아래 소재 DB(카탈로그 파일)도 함께 스냅샷을 뜬다.
3. 두 스냅샷을 diff하여 등록 전/후 변화를 비교한다.

가설: 소재 인식은 폴더 내 파일 존재 여부가 아니라 **소재 DB 등록 여부**를 기준으로 한다. 폴더에 파일이 생겨도 DB에 등록되지 않으면 팔레트에 나타나지 않을 가능성이 크다. 이 가설이 맞으면, 클립스튜디오 자동 연동은 파일 복사만으로는 불가능하고 별도 등록 방법이 필요하다는 뜻이며, MVP 범위를 벗어난다(`CLAUDE.md` §2 "클립스튜디오 자동 실행" 제외 항목과 동일한 결).

---

## 8. 미결정 / 리스크

- macOS에서 Documents 앨리어스와 실제 Library 경로 중 어느 쪽을 탐지 기준으로 삼을지 별도 확인 필요
- 클립스튜디오 미설치 환경에서 관련 경로 탐지 로직이 오류 없이 동작해야 함(선택 사항으로만 노출)
- 소재 DB 파일 포맷과 등록 방식은 비공개일 가능성이 높아, 스파이크 결과에 따라 클립스튜디오 직접 연동 자체가 불가능하다고 결론 날 수 있음
