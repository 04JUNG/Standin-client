# 빠른 3D 미리보기의 OFFSET 포즈 전달

2026-11-12. 작은 포스터와 내보낸 FBX에 비해 큰 3D 미리보기의 고개·몸통이
펴져 보이는 문제를 수정한다. 회전·스킨·외곽선 UI와 기존 로컬 모델 캐시는 유지한다.
버전 변경이나 배포는 포함하지 않는다.

## 원인과 구현

일부 단일 프레임 라이브러리 BVH는 모든 관절에 6개 채널을 선언하지만, 비루트
위치 채널은 거의 0이고 자세를 계층의 OFFSET에 저장한다. 기존 브라우저 코드는
흉곽·목·머리의 회전 델타만 옮겨 이 형식의 자세를 놓쳤다.

Converter는 `_offset_delta_pose`로 이 형식을 식별하고,
`converter/source_body.py::apply_source_body`로 평가된 관절 방향을 전달한다.
클라이언트에 같은 형식 식별 조건과 위치 기반 전달 단계를 추가했다. 골반 프레임,
척추 방향과 어깨선 roll, 목·머리 끝 방향, 어깨·팔다리 순으로 적용하며 대상 모델의
뼈 길이와 기존에 푼 twist를 보존한다. 퇴화 방향과 0.5°/175° 가드는 Converter와 같다.
이 단계는 기존 authoring corrective 다음, 손가락 포즈 적용 전에 실행한다.

develop의 #209 통합 후에는 회전 채널이 거의 0인 검토된 형식의 `bakedOffsets`
직접 보존 경로를 우선한다. 이 경로는 기존 규칙대로 neutral-rig corrective를
건너뛰며 새 전달 단계를 중복 적용하지 않는다. OFFSET과 유효한 회전 델타가 함께
있어 직접 보존 경로에 들어가지 않는 형식에만 새 전달 단계를 적용한다. 두 경로를
각각 검증하며 일반 motion BVH의 분기는 유지한다.

일반 회전 BVH와 절대 위치 채널을 쓰는 다른 6채널 형식에는 새 단계를 적용하지
않는다. 원본 BVH·표면·카메라·저장 결과를 변경하지 않는다. 네트워크 요청이나
서버 변환을 추가하지 않고 기존 큰 미리보기의 실제 3D 표면을 보정한다.

## 검증

- 합성 OFFSET 포즈에서 머리 끝 방향, 목·몸통·골반·팔다리 방향, 대상 뼈 길이,
  행렬/관절 위치 일치, 입력 불변을 검증했다. 일반 motion BVH, 복수 프레임,
  비델타 위치 형식을 구분하는 회귀 검사를 추가했다.
- 충돌 통합 회귀: OFFSET+루트 yaw 15° 혼합 입력의 자세 보존, #209 직접 보존
  입력의 관절 위치 유지와 두 번째 전달 생략을 확인했다.
- 기존 Blender 어깨 golden 8개와 반신 cap 회귀 검사도 유지한다.
- 제공된 `문장검색_standin_pose (7).fbx`를 읽기 전용으로 가져와 관절 위치를 추출하고
  동일 OFFSET 형식의 검수 입력을 재구성했다. 이 입력에서 기존 목→머리 방향 오차는
  15.3633°, spine2→neck은 10.1133°였고, 수정 후 각각 0° / 0.0000013° 미만이다.
  검사한 몸통·팔다리 12개 방향의 최대 오차는 0.000002° 미만이다. 원본 검색 BVH를
  직접 확보한 동일 job 재실행이나 표면 정점 전체의 FBX 동등성 검사는 아니다.
  이 수정 전후 측정은 #209 통합 전 기준이다.
- 로컬 Node에서 관절 전달 단계 120회 측정: p50 0.0425ms, p95 0.0843ms,
  최대 0.1948ms. 기존 스키닝·네트워크·GPU 표시 시간은 제외한 추가 단계 측정이다.
- 브라우저 WebGL에서 수정 전/후 머리·몸통을 비교하고 같은 3D 표면을 45° 회전해
  회전 기능을 확인했다. 검수 파일과 사용자 FBX는 저장소에 포함하지 않는다.
- #209 충돌 통합 후 전체 테스트 1,571개 통과, 외부 자산 검사 5개 skip. lint 오류 0(기존 경고 2개),
  typecheck·production build·diff 공백 검사 통과.
