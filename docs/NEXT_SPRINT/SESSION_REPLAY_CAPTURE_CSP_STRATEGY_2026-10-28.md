# 사용자 작업 리플레이·캡처 과정·CSP 결과 확인 전략

- 작성: 2026-10-28
- 상태: 사용자 구현 지시 반영 / 클라이언트·BFF 별도 워크트리에서 구현
- 기준: 각 저장소의 작업 시작 시점 최신 `origin/develop`
- 이번 결과물: 구현·검증·develop 대상 Draft PR. **운영 배포·운영 설정 변경·머지는 하지 않는다.**

## 1. 목표

기존 대시보드의 단계별 시간·실패·화면별 기능 지표에서 실제 사용 장면을 열어 본다. 러프를 어떻게 캡처했는지, 후보를 어떻게 골랐는지, 저장 이후 CSP에 제대로 표시됐는지를 하나의 작업 흐름으로 연결한다.

> 캡처 시작·영역 선택 → 러프 제출 → 분석·후보 확인 → 포즈·체형·손 변경 → 파일 준비·실제 저장 → CSP 적용 결과 확인

리플레이는 사용자가 한 행동과 보인 화면의 증거다. 후속 행동이 없다는 사실만으로 이탈 의도·포즈 불만족을 확정하지 않는다. 파일 저장·드래그 종료·CSP 창 활성화만으로 CSP 적용 성공을 기록하지 않는다.

## 2. 이번 작업의 동의 가정·기본 플래그

사용자 지시: 품질 검토 참여를 위한 새 동의 UI는 나중에 만들고, 이번에는 기본적으로 동의한 상태를 가정하며 플래그를 기본 ON으로 구현한다.

| 설정 | 개발 기본값 | 의미 |
|---|---|---|
| `REPLAY_ENABLED` / 클라이언트 대응 설정 | `true` | 앱 작업 리플레이 수집·재생 기능 |
| `CAPTURE_REPLAY_ENABLED` / 클라이언트 대응 설정 | `true` | 사용자가 시작한 캡처 과정 기록 |
| `CSP_RESULT_CAPTURE_ENABLED` / 클라이언트 대응 설정 | `true` | CSP 결과 화면 보내기 기능 제공 |
| `REPLAY_CONSENT_MODE` / 클라이언트 대응 설정 | `assumed` | 이번 개발·스테이징의 동의 가정 경로 |

위 이름은 계약 제안이며 실제 환경 변수 이름은 두 저장소가 합의해 고정한다. 누락 시 OFF로 내려가는 설정으로 사용자 지시를 뒤집지 않는다. 명시적으로 `false`를 주면 수집을 중단할 수 있어야 한다.

- `assumed`는 테스트용 수집 자격이다. 기존 개인정보·콘텐츠 동의 행을 `true`로 덮어쓰거나 동의 증빙을 만들어내지 않는다. 기록에는 `authorizationMode: assumed` 등 실제 권한 출처를 남긴다.
- 설치 인증·기록 소유권·관리자 인증은 그대로 필요하다. 동의 가정은 익명 업로드나 다른 설치 기록 열람 허용이 아니다.
- 명시적인 철회·삭제 요청은 가정 모드보다 우선한다. 중단·대기 업로드 폐기·서버 삭제 경로를 유지한다.
- 가정 모드의 실행·수신은 개발·스테이징으로 제한한다. `production`에서 가정 모드를 켠 채 실행하면 수집·자산 열람을 거부하고 진단 가능하게 한다. 운영 도입에는 나중에 만들 실제 동의 경로를 연결한다.
- 이번 작업에서 운영의 설치·동의·AWS·배포 설정을 바꾸지 않는다. 기존 운영에 조용히 수집을 시작하지 않는다.
- 캡처·CSP 결과 전송에는 필요한 OS 권한을 정상 요청한다. 동의 가정으로 macOS/Windows 권한을 우회하지 않는다.

## 3. 1차 구현 범위

| 범위 | 남길 내용 | 사용자 동작 |
|---|---|---|
| 앱 리플레이 | 화면 구조·변화, 클릭·스크롤·탐색, 창 크기·표시 상태 | 활성 앱 작업 구간을 기록 |
| 두 화면 연결 | 전체화면·플로팅 바·캡처 오버레이 전환과 공백 | 기존 흐름 그대로 사용 |
| 러프·검색 | 제출 이미지·화면 표시 상태, 자연어 검색 입력 변경·실행·재검색 | 기존 입력 흐름 유지 |
| 후보·체형·손 | 당시 후보 순서·자산 버전, 선택 변경·수치 변경·적용 결과 | 기존 조작 유지 |
| 대기·오류·저장 | 시작·완료·재시도·취소·오류·실제 저장 성공 | 실제 계측과 동일한 작업/시도에 연결 |
| 캡처 과정 | 캡처 배경, 커서·선택 사각형 변화, 재선택·확정·취소 | 사용자가 캡처를 시작한 동안만 |
| CSP 결과 | 사용자가 지정한 CSP 창/캔버스의 결과 이미지 1장과 작업 연결 | ‘적용 결과 보내기’ 버튼·단축키 |
| 관리자 재생 | 목록·필터·타임라인·장면 이동·러프/최종/CSP 비교 | 기존 대시보드에서 열기 |

CSP 짧은 영상은 후속 확장이다. 이번 완료 조건은 CSP 결과 이미지와 앱·캡처 과정의 재생이다. 다른 앱/바탕화면을 상시 녹화하거나 마이크·오디오를 기록하지 않는다. CSP의 비공개 문서·레이어 내부 구조를 읽는 기능도 추가하지 않는다.

로그인 비밀번호·인증 토큰·쿠키·보안 저장소·로컬 전체 경로는 리플레이에서 제외한다. 인증 화면은 수집 대상에서 제외한다. 검색어는 사용자가 요청한 대상이므로 일반 입력 전체를 무차별 수집하는 대신 검색 입력 영역을 명시적으로 허용한다. 로그·네트워크 본문 전체 수집을 기본으로 켜지 않는다.

## 4. 앱 리플레이의 기술 방식

우선 후보는 `rrweb` 기반의 화면/행동 기록·재생이다. 최신 공식 패키지 구성을 확인해 버전을 고정하고 앱 번들과 관리자 플레이어에 포함한다. 러프를 취급하는 재생 화면이 제3자 CDN 스크립트에 의존하지 않게 한다.

- DOM·이벤트 기록과 기존 제품 이벤트를 연결한다. 분석·후보·선택·준비·저장 이벤트를 녹화 엔진에서 추정해 다시 만들지 않는다.
- 이미지/폰트/스타일/blob URL은 과거 화면을 복원할 수 있도록 자산 처리 계약을 만든다. 만료된 presigned URL만 저장하는 방식은 불가하다.
- 후보 목록은 당시 순서·방향·선택 상태와 자산 해시/버전을 보관한다. 같은 포즈 ID의 최신 썸네일로 과거 화면을 바꾸지 않는다.
- 3D/WebGL은 DOM만으로 재현된다고 가정하지 않는다. 모델 상태 변경 이벤트와 지원되는 캔버스 프레임을 연결한다. 우선 상태 변화 시점·회전 중 저빈도 프레임을 시험하고, 미지원 환경은 ‘3D 기록 누락’으로 표시한다.
- 초기 제안은 3D 활성 조작 중 최대 2fps, 정지 상태는 변화 시점이다. 실제 Tauri WebView와 두 OS에서 부하·화질을 측정해 확정한다. 60fps 영상 저장을 요구하지 않는다.
- 업로드/녹화 오류는 제품의 분석·저장 성공 여부와 별개다. 녹화 실패 때문에 본래 작업을 차단하지 않는다.

## 5. 캡처 화면 자체의 재생

1차 방식은 기존 캡처 배경 이미지에 마우스 위치·선택 영역 변화를 결합해 재생하는 것이다. ‘실시간 바탕화면 영상’과 구분해 `capture_overlay_reconstruction`처럼 기록 방식을 남긴다.

1. 사용자가 캡처를 시작하면 입력 시도 ID와 캡처 스트림을 만든다.
2. 기존 오버레이에 쓰인 배경 프레임과 원점·모니터·DPI·논리/물리 좌표 변환 정보를 묶는다.
3. 커서 이동·드래그 시작/끝·선택 사각형·재선택·확정·취소를 기록한다. 움직임은 샘플링하고 확정 좌표는 원본 정밀도로 보관한다.
4. 최종 크롭 이미지와 실제 분석 작업이 생기면 같은 입력 시도에 연결한다. 취소로 작업 ID가 없어도 세션에서 재생 가능해야 한다.
5. 재생 시 배경과 선택 박스를 원래 비율·좌표에 맞춰 합성한다. CSP 창/허용 캡처 영역 밖의 배경은 가릴 수 있게 수집 전에 처리한다. 다른 화면의 토큰·알림·암호 입력 등이 배경 사본에 섞이지 않도록 캡처 자산 범위를 검사한다.

캡처 오버레이가 WebView 밖이거나 별도 창이면 recorder를 각각 연결하거나 공통 시계로 합성한다. 전체화면 recorder 하나를 켜고 네이티브 오버레이가 자동 기록된다고 주장하지 않는다. 원래 캡처의 숨김·포커스·ESC·단축키·다중 모니터 동작을 깨지 않는다.

## 6. CSP 적용 결과 확인

- 최종 저장 뒤 ‘적용 결과 보내기’를 제공한다. 사용자가 CSP에 불러온 다음 버튼/단축키로 결과가 보이는 시점을 알려준다.
- 특정 CSP 창 또는 사용자가 지정한 캔버스 영역만 이미지로 받는다. macOS는 ScreenCaptureKit 등, Windows는 해당 창 캡처 API를 조사해 OS별 어댑터로 구현한다.
- CSP 창이 여러 개거나 대상이 바뀌면 대상을 확인할 수 있게 한다. 파일명/경로만으로 창을 추측해 잘못된 문서를 찍지 않는다.
- `jobId`, 최종 산출물 해시, 선택 스냅샷 버전과 연결한다. 작업 없이 임의 캡처가 최신 작업으로 붙지 않게 한다.
- 캡처 성공은 `csp_result_captured`이다. 사용자의 명시적 확인 없이 `csp_import_succeeded`로 승격하지 않는다. 화면에 인형이 있다는 사실만으로 우리 FBX임을 자동 확정하지 않는다.
- ‘잘 나왔어요 / 이상해요 / 불러오지 못했어요’ 같은 간단한 사용자 평가를 선택적으로 붙일 수 있다. 결과 사진과 사용자의 판정을 분리해 보관한다.
- CSP가 없거나 권한 거부·최소화·대상 닫힘·빈 프레임이면 이유와 재시도를 제공한다. 기존 FBX 저장을 실패 처리하지 않는다.

## 7. 세션·작업 연결 계약

공통 키 제안:

| 키 | 목적 |
|---|---|
| `replayId`, `appSessionId` | 녹화와 앱 사용 세션. 두 창에서 독립 생성한 ID를 같은 세션으로 잘못 간주하지 않음 |
| `windowInstanceId`, `surface` | `app`·`bar`·`capture`별 스트림과 창 재생성 구분 |
| `installationId`, `environment`, `appVersion`, `os` | 설치 소유권·내부 테스트·환경·버전별 필터 |
| `inputAttemptId`, `jobId`, `attemptId` | 작업 생성 전 캡처, 생성 후 분석·준비·저장 시도 연결 |
| `sequence`, `timestamp`, `monotonicOffset` | 청크 정렬·재전송·공통 타임라인·시계 오차 처리 |
| `assetId`, `contentHash`, `snapshotVersion` | 원본·썸네일·최종 결과의 당시 버전 고정 |
| `authorizationMode`, `policyVersion` | 가정 모드와 실제 동의 경로를 구분 |

네이티브 호스트 또는 창 간 조정자로 앱 세션 기준을 공유한다. 숨겨진 창·백그라운드·휴식은 별도 상태다. 구간 경과 시간과 실제 활동 시간을 섞지 않는다. 강제 종료·순서 누락·자산 만료는 재생 공백으로 표시하며 이탈/실패 원인을 꾸며내지 않는다.

## 8. 업로드·저장·삭제

```text
클라이언트 recorder/캡처 어댑터
  → 제한된 로컬 큐·압축 청크
  → 설치 인증이 있는 BFF 수집 API
  → 비공개 객체 저장소 + DB 메타데이터·인덱스
  → 관리자 인증·열람 감사
  → 격리된 플레이어 + 기존 지표 타임라인
```

- 5~10초 단위 청크를 시작점으로 시험한다. 주기적 전체 스냅샷을 포함해 재생 시작점과 중간 탐색이 가능해야 한다.
- 청크는 설치·replay·stream·sequence에 귀속시킨다. 재시도는 멱등 처리하고 순서 역전·누락·마지막 미전송을 표현한다.
- 파일 크기·세션/일 용량·메모리·로컬 큐 수명·네트워크 재시도에 상한을 둔다. 구체값은 스테이징 측정으로 확정하고 상한 초과는 공백 사유로 남긴다.
- 초기에는 대상 개발/스테이징 세션 100%를 기록한다. 이후 표본 수집·오류 전후 버퍼를 도입해도 기존 지표 집계는 표본 추출과 분리한다.
- 리플레이·캡처 배경·CSP 결과 이미지는 초기 **14일** 보관한다. 원본 러프/연결 작업의 더 이른 만료·삭제·철회가 우선한다. 별도 사본으로 원본 보관 기간을 연장하지 않는다.
- 작업 삭제는 해당 작업 연결과 자산을 제거한다. 한 세션에 다른 작업도 있으면 나머지를 삭제하지 않되, 삭제 작업의 화면·텍스트·이미지가 리플레이 이벤트에 남지 않도록 관련 청크를 재작성하거나 제거한다. 안전하게 부분 제거할 수 없으면 해당 녹화 전체를 삭제한다.
- 삭제 요청은 DB 목록뿐 아니라 객체·파생 프레임·썸네일·발급 URL 캐시까지 처리한다. 이미 발급된 URL의 짧은 만료와 삭제 후 접근 차단을 고려한다.

## 9. 대시보드 재생 — 완료 필수 범위

기존 대시보드 항목은 유지하고 ‘사용 흐름’·오류 상세·작업 상세에 ‘관련 세션 보기’를 붙인다. 별도 스프린트용 샘플 페이지에서만 보이는 것으로 완료하지 않는다.

- 세션 목록: 기간·환경·내부 테스트·OS·앱 버전·전체화면/플로팅 바·기능·오류·저장 결과 필터.
- 플레이어: 재생/일시정지·배속·시간 이동·무활동 건너뛰기·창/화면 구분·기록 누락 표시.
- 타임라인: 캡처·분석·결과·선택·체형·손·준비·저장·CSP 결과 이벤트 표시. 오류를 누르면 직전 장면으로 이동.
- 비교 패널: 입력 러프·최종 포즈 이미지·CSP 결과 사진과 사용자 평가를 나란히 표시. 측정된 단계 시간·오류 코드와 연결.
- 보존 기간 종료·삭제·미수집·권한 없음·업로드 미완료를 ‘검은 화면’ 하나로 숨기지 않는다.

플레이어는 기록된 DOM을 신뢰하지 않는다. 관리자 화면과 격리하고 스크립트·폼 제출·외부 네트워크·Tauri IPC·탐색을 차단한다. 재생이 실제 앱 조작이나 원본 사용자 세션의 재실행이 되면 안 된다. 이미지 자산은 관리자 권한으로 제한해 제공하고 토큰을 녹화 URL이나 HTML에 포함하지 않는다.

## 10. 클라이언트·BFF 역할

| 담당 | 소유 범위 |
|---|---|
| 클라이언트 | recorder, 창 간 세션, 로컬 큐·압축·전송, 제품 이벤트 연결, 캡처 오버레이 재생 데이터, 3D 기록, CSP 결과 캡처·UI, 플래그·가정 모드, 오류 복구 |
| BFF | 인증된 수집 계약, DB·객체 저장·인덱스, 제한·검증·멱등성, 보관·삭제·가정 모드 경계, 관리자 검색·자산 API, 기존 대시보드의 실제 플레이어·지표 연결 |

BFF가 초기에 버전 고정 JSON 계약과 샘플 요청·응답·오류·자산 MIME/제한을 공유한다. 클라이언트는 그 계약을 실제로 사용한다. 양쪽이 서로 다른 임의 API를 만들고 나중에 붙이겠다고 끝내지 않는다.

필요한 저장소/권한은 구현·IaC 제안과 로컬 테스트로 준비한다. AWS 리소스 생성·운영 서비스 재배포는 이번 권한 범위가 아니다. 운영용 관리자 토큰이나 원고를 테스트 fixture로 커밋하지 않는다.

## 11. 검증과 완료 기준

1. 최신 develop SHA·각 독립 워크트리·codex 브랜치·플래그 기본값을 기록한다.
2. 개발·스테이징 가정 모드에서 별도 새 동의 UI 없이 수집·업로드·재생이 작동한다. 명시 OFF와 철회·production 가정 모드 거부를 검증한다.
3. 전체화면→플로팅 바→캡처→결과→저장 작업을 실제로 기록하고 BFF를 거쳐 대시보드에서 재생한다. mock 화면만으로 완료하지 않는다.
4. 캡처 취소·드래그 재선택·다중 모니터·DPI·창 크기 변경과 배경/커서 정합성을 확인한다.
5. 후보 이미지·검색어·포즈/체형/손 변경·3D 프레임·타임라인이 당시 상태를 보인다.
6. CSP 결과 이미지가 올바른 작업·FBX 버전에 연결되고, 저장 성공과 CSP 확인이 구분된다.
7. 권한 거부·대상 창 닫힘·순서 누락·오프라인·전송 재시도·종료 직전 손실·자산 만료가 재생 상태에 정확히 나타난다.
8. 관리자/설치 간 접근 분리, 크기 제한·파일 유형·재생 격리·인증정보 제외·철회/작업 삭제·14일 만료를 검증한다.
9. 녹화 ON/OFF의 반응 시간·3D 프레임률·메모리·분당 업로드 크기를 비교해 보고한다. 검색·저장·캡처 기존 동작 회귀가 없어야 한다.
10. macOS와 Windows 지원·미검증 범위를 구분한다. 실행할 수 없는 OS를 테스트 완료로 보고하지 않는다.
11. 양쪽 develop 대상 Draft PR을 만들고 연동 테스트 결과·미완료 항목을 남긴다. **머지·릴리스·운영 배포하지 않는다.**
