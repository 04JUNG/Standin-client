# 직접 문장 검색 전체 결과 표시

입력: `POST /v1/semantic-search {"query":"공을 던지는 자세","topK":null}`.
서버의 `topK:null` 전체 반환 변경(#107)이 포함된 추론 766ce81/task67이 스테이징에 배포됨을 확인했다.
변경 전 BFF에는 null이 5로 치환되어 실제 스테이징 조회 결과가 5개였다. BFF #99가 이 변환과 20개 상한을 제거한다.

- 앱·플로팅 바 동일 공유 목록. 20개씩 자동 추가하고 앞선 카드는 남긴다. 키보드용 더 보기 버튼도 제공한다.
- 65개 정식 후보·27개 참고 후보를 각각 분리하고 끝까지 탐색한다. 스크롤은 추가 API 요청이 아니다.
- 상단 검색창에서 300ms 자동 재검색, 조합 입력 대기, Enter 즉시 검색, 중복 요청 억제, POST/GET 취소 및 늦은 응답 차단.
- 다음 결과 JSON을 먼저 받아 캐시에 넣고 이동한다. 입력 DOM/focus를 보존하고 새 결과는 첫 행으로 이동한다.
- 기록·뒤로 가기로 다른 job을 열 때 검색어 동기화 및 진행 중 요청 취소.
- 인증·출처·해시를 검증한 저장 포스터만 화면 가까이에서 읽는다. 없는 포스터는 3D 작업으로 대체하지 않는다.
- 상세를 명시적으로 열 때 기존 체형/3D 미리보기를 요청한다. 수동 저장 권한과 최종 확인은 기존 계약을 유지한다.
- 러프 분석 API 및 Top-5 변경 없음.

## 다른 로컬 UI 작업과의 관계

별도 세션의 로컬 96bcedd 작업에서 검색창/공유 훅 형태를 재사용했다. 이 PR은 해당 문구 개선 전체 커밋이나
후속 회색 안내 제거 커밋 dbc797c를 포함하지 않는다. 그 세션 워크트리 및 커밋은 수정하지 않았다.
검색창 관련 파일을 양쪽에서 합칠 때는 이 PR의 전체 결과·300ms·취소·스크롤 동작을 유지해야 한다.

## 검증 범위

실제 생산 컴포넌트의 격리된 로컬 UI fixture로 전체 화면 1280×800, 바 720×560에서 65/65 및 27/27 도달,
검색창 상단 유지, 바 420×640에서 3열·가로 넘침 없음 확인. 같은 기존 인체 PNG를 반복한 배치 검증이며
92개 서로 다른 포즈의 실제 렌더 검증이나 설치 앱/새 BFF의 스테이징 E2E 완료를 뜻하지 않는다.

초기 구현에서 빠른 바 스크롤이 sentinel을 건너뛰는 문제를 재현하고, observer와 스크롤 위치 확인을 병행해 고쳤다.
단위 테스트는 debounce/IME/Enter/취소/결과 GET 지연·기록 이동·설치 소유자, 전체 결과 보존,
앱/바 목록 추가 및 선택, 저장 PNG lazy load·미존재 시 3D 폴백 금지를 확인한다.

배포 순서: 추론 전체 반환 버전 → BFF #99 → 이 클라이언트 → 최신 설치 빌드 실제 검색/내보내기 검증.
후보 개수에 따라 BFF의 기존 BVH 해시 확인 시간·전체 JSON 수신 시간은 증가할 수 있으므로 별도 계측이 필요하다.
