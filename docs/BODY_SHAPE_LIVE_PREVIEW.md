# 체형 선택 UX 정리와 실시간 체형 미리보기 계획

작성: 2026-10-15 · UX는 `codex/shapekey-body-ux`, 실시간 렌더는 `codex/shapekey-live-render` (develop 기준, 미커밋) · 관련 문서 [BODY_SELECTION_UI.md](BODY_SELECTION_UI.md)

이 문서는 세 가지를 남긴다: 지금까지 구현한 체형 선택 UX, 새로 만들 실시간 체형 렌더링, 그리고 구현할 때 신경 써야 할 부분. 수치 중 **추정**이라고 적힌 것은 측정값이 아니다. 시제품에서 다시 잰다.

## 1. 지금까지 구현한 UX

### 흐름

```text
포즈 후보 Top-5
 → 인물 줄의 [포즈 | 체형 더보기] 토글
 → 체형 더보기: [내 체형(왼쪽, 큰 박스) | 프리셋 줄(오른쪽)] + 체형 조절 바
 → [포즈]로 돌아가면 새 체형으로 다시 그린 Top-5
 → 포즈 선택 → 기존 검토·저장 화면(변경 없음)
```

### 화면 요소

| 영역 | 동작 |
|---|---|
| 원본 패널 | `이 인물`은 인물 상자대로 자른 러프(상자 밖은 clipPath로 잘라 옆 인물이 섞이지 않음), `전체`는 원본 위 인물 상자. 상자를 누르면 그 인물로 이동. |
| 포즈/체형 토글 | 코랄 배경이 좌우로 미끄러지는 세그먼트 토글. 예전 `체형 더보기 닫기` 버튼을 대체. |
| 체형 더보기 | 남성/여성/아동 탭. 왼쪽 **내 체형** 박스, 오른쪽 **프리셋 줄**(2절). 프리셋을 누르면 바로 이 인물에 저장(포즈 선택은 유지). |
| 체형 조절 바 | 남성 키·등신·체격·근육·근육 볼륨·어깨, 여성 키·등신·어깨너비·근육량·지방·지방 볼륨·가슴 크기 + 세부 조절. 손을 뗀 뒤 0.6초 쉬면 저장, 저장 중 더 움직이면 끝난 뒤 마지막 값을 보냄. `자동 추천` / `내 기본값` / `초기화`. 남성만 조절 가능, 여성·아동은 고정 체형. |
| 인물별 `선택` 스위치 | 끄면 그 인물은 포즈를 고르지 않아도 진행되고 확정 요청에서 빠짐. 다시 켜면 이전 선택 복원. (예전 용어 `내보내기` → `선택`) |
| 앱 화면 | 원본 개요 카드, 펼친 인물 카드, 접힌 인물 줄은 줄 전체가 버튼(호버 시 옅은 배경과 ›). 하단 `이전 인물` · `다음 인물로` / `이 포즈 사용하기 (n/m)`. |
| 플로팅 바 720×560 | 원본 패널(폭 26%, 최소 180px) + 후보 위 3·아래 2 가운데 정렬. 카드는 정사각형 비율 유지(FitTile, container query). 체형 더보기가 창보다 길어지면 그 칸 안에서만 스크롤. |
| 설정 | `설정 › 체형 기본 설정 › 내 기본 체형 수치`. 서버가 `shapeEditable`을 줄 때만 보임. |
| 제거한 것 | 후보 화면의 출력 범위 선택(서버 자동 판별값 사용). 인물별 다시 찾기(서버 엔드포인트 없음, `capabilities.candidateRerun` 슬롯만 둠). |

### 진행·확정 조건

- 진행: `선택한 인물 ≥ 1` 그리고 `선택한 인물 전원이 포즈를 고름`.
- 확정: 선택한 인물만 보낸다. BFF는 확정 시 선택에서 빠진 인물의 기존 확정 행을 지운다.

### BFF 계약 `body-shape.v1`

- 카탈로그 자산: `shape { schemaVersion, controls[{ key, min, max, step, default }] }`
- 인물 선택: `shape { schemaVersion, controls, shapeSha256 } | null`
- 설정: `shapeDefault`, `shapeEditable`
- `BODY_SHAPE_EDIT_ENABLED`로 막혀 있다. 수치 체형이 있는 선택의 미리보기·FBX는 `409 BODY_SHAPE_RENDER_UNSUPPORTED`로 거절한다(converter가 아직 수치를 굽지 못함). 카탈로그에서 shape 규격이 사라지면 선택을 사용 불가로 재검증한다.

### 테스트

클라이언트 vitest 531 통과(`codex/shapekey-live-render`, 남성 0.6.10 실시간 렌더 테스트 포함), BFF node:test 362개 중 360 통과·2 건너뜀. 클라우드에서 Mac의 node_modules로 돌린 결과다. Mac에서 `npm ci && npm test`와 Tauri 실행 확인이 남아 있다.

## 2. 체형 더보기 레이아웃 (2026-10-15 변경)

```text
┌ 내 체형 ─────────┐ │ 프리셋 · 누르면 그 체형으로 바뀌어요
│ [원본]            │ │ ┌선택됨┐ ┌──────┐ ┌──────┐ ┌──────┐ →
│      (실시간)      │ │ │ 기본 │ │8.3등신│ │7등신 │ │6.4등신│
│                   │ │ └──────┘ └──────┘ └──────┘ └──────┘
│ 기본 수정          │ │        (고정 그림, 가로 스크롤)
└───────────────────┘ │
[ 체형 조절 바 ··· ]  [자동 추천] [내 기본값] [초기화]
```

- **내 체형(왼쪽, 큰 박스)**: 지금 이 인물에 고른 체형 + 손대는 중인 값. 조절 바를 움직이면 **이 박스만** 다시 그린다. 왼쪽 위에 원본 러프를 작게 겹쳐 비교한다. 예전 맨 앞 고정 원본 카드를 대신한다.
- **프리셋 줄(오른쪽)**: 서버의 고정 미리보기 그림이다. 조절 바와 무관하게 움직이지 않고, 고른 프리셋에 `선택됨`만 붙는다.
- 크기: 앱은 내 체형 232×248(그림) / 프리셋 140×196, 바는 150×150 / 96×120.
- 구현: `src/features/body-selection/LiveBodyView.tsx`의 `LiveBodyView`, 프리셋 줄은 `BodyCandidates.tsx`의 `BodyExpand`.

### 지금 무엇이 실제로 움직이나 (2026-10-15 실시간 렌더 구현 후)

| 조건 | 내 체형 박스 |
|---|---|
| 카탈로그가 `shapeRuntime`(규칙 `standin-body-0.7.1`·`0.6.10`·`0.6.7`·`standin-female-body-0.3.3`·`0.2.2`)을 주고 자산 검증·WebGL 성공 | **그 모델을 앱에서 계산해 three.js로 그린다.** 바를 움직이면 다음 프레임에 다시 그림 |
| 자산을 받는 중 | 고른 체형의 고정 그림 + "3D 체형 불러오는 중" |
| 자산 없음·규칙 다름·검증 실패·WebGL 실패 | 고정 그림 + "수치 미리보기를 쓸 수 없어요 · 지금은 처음 모양만 보여요" |
| 개발용 Mock에서 자산 파일이 없을 때 | canvas 실루엣(실제 렌더 아님) |

구현: `LiveBodyView.tsx`(분기), `shapeRuntime/format.ts`(자산 검증), `shapeRuntime/evaluate.ts`(규칙별 계산: `male071.ts`·`female033.ts`(+`anatomy.ts`·`mesh.ts`)·`male0610.ts`·`male067.ts`·`female022.ts`), `shapeRuntime/mountShapeBody.ts`(three.js), `shapeRuntime/load.ts`(받기·sha256 검증·캐시). 자산 만들기: `scripts/shape-runtime/`.

## 3. 실시간 체형 렌더링 (구현됨, 2026-10-15)

목표: 실서버 모드에서도 조절 바를 움직이면 내 체형 박스의 3D 모델이 즉시 커지고 줄어든다. 기준 모델은 `standin-body-0.6.7`(asset `standin-upperbody-451353a0177755b5f20f`). 최종 FBX는 지금처럼 서버(converter)가 만든다. 앱 렌더는 **미리보기**다.

### 3.1 0.6.7의 중립 체형 계산 (standin_body.py)

```text
controls(UI 값)
 → mappings(c): 체형 키 가중치 (마름/지방 3부위, 근육 7부위, 선명도, 흉곽·허리·엉덩이·허벅지·종아리)
 → compose_body: Basis + Σ wᵢ·deltaᵢ  (+ 고지방 평활 혼합, 팔 지방 추가, 근육 아래 연한 볼륨,
                 근육 초과분 마스크, 선명도 법선 성분×5, 지방 아래 근육 윤곽 완화, 턱 위 지방 차단)
 → fat_connection_offset: 허리–엉덩이–허벅지 띠에서만 36회 평활 차이 + 정점별 길이 제한
 → 상체(z≥1.18~1.30) 0.6.0 분포 유지 혼합, 근육 1~2에서 0.6.0 분포로 전이
 → warp: 키·등신·몸통/팔/다리 길이·허벅지:종아리·어깨·골반·머리·목을 정점별 닫힌 식으로 변환
 → fold_guard: 최종 공간에서 면 뒤집힘 반복 수리
```

핵심 관찰: 평활화는 모두 **선형 연산**이고, 체형 값에 따라 바뀌는 것은 **스칼라 가중치**뿐이다. 따라서 무거운 평활화 결과는 Blender에서 미리 계산해 두고, 앱에서는 "미리 계산한 필드 × 가중치의 합 + 정점별 닫힌 식"만 하면 된다.

### 3.2 구현한 구조

1. **자산 굽기** `scripts/shape-runtime/build_runtime.py` — .blend를 직접 읽고(Blender 불필요), `asset_lock` 해시로 추출을 확인한 뒤 컨트롤러를 bpy 없이 불러 필드를 굽고 92조합으로 대조한다.
2. **형식** `standin-shape-runtime.v1`: `"SSR1" | u32 머리 크기 | 머리 JSON | 데이터`. 기준 메시 float32, 삼각형 u16, 필드는 희소(정점 번호 u16 + int16×scale), 띠 필드는 int16×bandScale. 머리에 규칙·asset·랜드마크·컨트롤 범위/기본값·프리셋·상수.
3. **계산** `evaluate.ts` — `resolveControls`(기본값 ← 프리셋 ← 앱 값, `height`→`height_cm`, 범위 자르기, 모르는 key 무시) → `mappings` → 계수 → 가중합 두 번(현재/0.6.0 지방) → 지방 연결 띠 → 상체·근육 혼합 → `warp`.
4. **그리기** `mountShapeBody.ts` — 마운트마다 새 캔버스(해제 시 컨텍스트를 강제로 잃게 하므로 재사용 금지), `DynamicDrawUsage` 위치 버퍼 + `computeVertexNormals`, 후보 카드와 같은 `libraryPreviewMaterial`. 틀은 키 195cm·T 포즈 팔 너비가 들어가는 고정 크기라 키를 바꾸면 크기가 실제로 변해 보인다.
5. **받기** `load.ts` — `GET /v1/models/:characterId/shape-runtime/:sha256`, 크기·sha256·형식·규칙·프리셋 검사, sha256 키로 한 번만 받음(모든 프리셋이 같은 자산).
6. **BFF** (`Standin-app-server`, 같은 브랜치) — manifest asset의 `shapeRuntime { path, sha256, bytes, format, rules, preset }` 검증(`shape` 없는 asset에 있으면 카탈로그 닫음), body-options에 메타데이터(경로 없음), 위 GET 경로(크기·`SSR1`·sha256 재검사, 편집 플래그 꺼지면 404). 테스트 359 통과·2 건너뜀.

## 3.5 내 기본값 (2026-10-16, 브랜치 `codex/shape-default-ux`)

"내 기본값" = 체형 하나 + (조절 가능한 체형이면) 그 수치. 서버에는 `defaultCharacterId`와 `shapeDefault`로 저장되고, 앱은 둘을 늘 같은 체형으로 맞춰 저장한다(`preferences.ts`의 `useMyDefault`). 예전 값이 어긋나 있으면 수치가 있는 쪽을 내 기본값으로 본다.

| 화면 | 동작 |
|---|---|
| 후보 화면 · 체형 더보기 | `내 기본값`(불러오기, 이 인물에 적용) 옆에 **`내 기본값으로 저장`**(지금 체형과 손대는 중인 수치를 저장). 지금 체형이 내 기본값과 같으면 `내 기본값과 같음`으로 잠기고 조절 바 제목에 ★내 기본값, 프리셋 카드에 ★내 기본이 붙는다. 저장 후 "모델 화면에서 보기" 링크(바 창에서는 안내 문구만). |
| 모델 화면(체형 기본 설정) | **내 기본값** 칸: 체형 종류 탭 + 이름이 보이는 체형 카드 줄 + 실시간 3D 박스(LiveBodyView 재사용) + 기본/세부 조절 바(후보 화면과 같은 `ShapeControlGrid`) + `내 기본값으로 저장`·`되돌리기`·`지우기`. 저장 안 된 편집은 박스에 "저장 안 됨". 조절할 수 없는 체형은 수치 없이 저장. |
| 모델 화면 · 새 작업을 시작할 때 | `자동 추천(기본)` / `내 기본값으로 시작 · {체형}`. 내 기본값이 없으면 두 번째는 잠긴다. 지우면 자동 추천으로 돌아간다. |

- 예전 화면의 "내 기본 체형" 선택 상자와 "내 기본 체형 수치" 칸은 위 한 칸으로 합쳤다(이름 대신 ID가 보이던 문제, 버튼 안내문이 "설정 › 체형 기본 설정"을 가리키던 문제 함께 해결).
- BFF(`Standin-app-server`, 같은 브랜치): `shapeEditable` 항목에 `displayName`·`neutralPreview`·`shapeRuntime`을 더했다(설정 화면이 작업 밖에서 체형을 그리려면 필요). 구 BFF면 이름은 모델 목록에서, 그림은 "미리보기 없음"으로 떨어진다.
- **하지 않은 것:** "내 기본값으로 시작"은 새 작업에 **체형만** 적용한다. 수치까지 자동 적용하려면 BFF 해석(`fixed_default`)이 `shapeDefault`를 선택에 붙여야 하고, converter가 수치를 굽지 못하는 동안은 그런 선택의 미리보기·FBX가 409로 막힌다. 그래서 수치는 후보 화면에서 `내 기본값`을 눌러 불러온다.
- 목업: 처음엔 내 기본값이 비어 있다. Mock 자산 정보의 sha256을 규칙마다 다르게 바꿨다(같은 값이면 앱 캐시가 남녀 자산을 섞어 여성 3D가 실루엣으로 떨어졌다).
- 테스트: `myDefault.test.tsx`(규칙·저장 형태·지우기), BFF `shape.test.ts`(설정용 메타데이터, 서버 경로 비노출).

## 3.6 슬라이더 값을 실제 포즈 FBX에 굽기 + 버전에 매이지 않는 미리보기 (2026-10-16, 브랜치 `codex/shape-bake-latest`)

목표: 슬라이더로 세밀하게 조절한 값이 **최종 FBX와 저장 결과 포즈에 그대로** 들어간다. 대상 남성 0.7.1, 여성 0.3.3
(작업 중 0.3.2 → 0.3.3으로 올라가 converter 등록·굽기 검증을 다시 했다).

**결과물은 converter가 굽는다(정확).** 앱은 선택에 저장된 수치를 그대로 쓰고, BFF가 converter `/convert-framed`에
수치와 "어느 원본으로 구울지"(`expected_shape_source`)를 함께 보낸다. converter는 승인된 .blend와
`standin_body.py`를 Blender에서 직접 실행해 수치를 굽고 → V3.2.5 solver → 컨트롤러 자세·접촉 보정 → 최종 FBX를
만든다. 검토 화면(PNG/GLB)도 그 FBX에서 나온다. 계약 정본: Standin-server `docs/API_CONTRACT.md`, BFF `docs/API.md`.

**실시간 미리보기는 두 경로.**

| 경로 | 언제 | 정확도 |
|---|---|---|
| v1 정밀 이식(SSR1, `male071.ts`·`female033.ts`, 위 "남성 0.7.1 · 여성 0.3.3으로 교체") | 규칙을 앱으로 옮긴 버전(지금 0.7.1/0.3.3) — **운영 카탈로그는 이것을 쓴다** | 컨트롤러와 0.006~0.025 mm |
| v2 표본(SSR2, `sampled.ts`) | 새 버전이 나왔는데 아직 이식 전 — 빌드만 돌리면 바로 쓸 수 있다 | 아래 표(근사) |

두 경로 모두 머리말에 원본 `source`(.blend·컨트롤러 SHA-256)를 담는다(`build_runtime.py`도 2026-10-16부터 기록).
v2 빌드: `scripts/shape-runtime/README.md`.

**버전 가드.** 카탈로그 asset `shapeSource{rules, blendSha256, controllerSha256}` = converter 레지스트리 원본 = 앱 자산
머리말 `source`일 때만 굽고 그린다. 앱: `load.ts`의 `matchesCatalog` — 다르면 실시간 3D를 끄고 고정 그림.
BFF: 원본이 다른 자산(SSR1/SSR2)은 서빙하지 않고, converter 계보가 다르면 무결성 오류. converter: 다르면 `409 SHAPE_SOURCE_MISMATCH`.
원본 해시가 없는 예전 v1 자산은 원본을 밝힌(굽기 연동) 체형에는 쓰지 않는다.
실자산 확인: 0.7.1/0.3.3 정밀 이식 SSR1 2개 + 20개 프리셋 카탈로그 → BFF 파싱·서빙 → 앱 가드 통과, 원본을 바꾸면 BFF·앱 모두 거절.

**v2 표본 정확도** (`check_sampled_runtime.py`, 빌드와 다른 시드의 독립 검사, 컨트롤러 대비 최대 정점 오차 mm, 중앙값):

| | 조절 2~6개 프리셋 근처 | 기본 조절 전부 전 범위 무작위 | 모든 조절 전 범위 무작위(스트레스) |
|---|---|---|---|
| 남성 0.7.1 (9 프리셋, 기저 176, 31.1 MB) | 0.1–0.6 (최대 7) | 1.6–4.4 (최대 8.7) | 4–10 (최대 17) |
| 여성 0.3.2 (11 프리셋, 기저 168, 32.8 MB, 0.3.3 직전 버전으로 측정) | 0.06–0.85, 슬림형 3.4 (최대 7.6) | 1.6–7.0 (일부 조합 최대 68) | 3–11 (최대 49) |

화면 박스(248px)에서 1px ≈ 8mm다. 보통의 조절은 1px 미만이다. 여성의 극단 조합(근육 0~4 × 지방 볼륨 0~2 × 지방
동시 극단)에서 수 px 차이가 날 수 있다 — 저장 전 검토 화면은 실제 FBX라 그 차이를 확인할 수 있다.
계산 시간: 값 한 번 19 ms(클라우드 CPU, 기저 160). 자산은 체형 더보기를 처음 열 때 한 번 받는다(남 31 MB, 여 33 MB).

**대기 시간.** 수치 굽기는 1회 30~110초(2 vCPU). 검토 화면은 수치 체형이 있으면
"조절한 체형을 실제 포즈에 반영하는 중… 1~2분 걸릴 수 있어요."를 보여 준다.

**하지 않은 것:** "내 기본값으로 시작"의 수치 자동 적용(BFF `fixed_default`가 `shapeDefault`를 선택에 붙이는 일)은
아직이다 — 굽기가 켜진 뒤 다음 단계로 한다. Mock/목업 HTML은 여전히 v1 자산(0.6.10/0.2.2)이다(v2 자산은 각 30 MB 이상).

## 4. 신경 써야 할 부분

### 4.1 성능 (측정값은 3절 표, 아래는 대응)

| 항목 | 현재 | 대응 |
|---|---|---|
| 앱 번들 | three.js 추가 없음(이미 사용 중) | — |
| 값 한 번 바꿀 때 | 계산+법선 약 17 ms(컨테이너 CPU 기준). 남성 0.6.10에서 근육 볼륨 > 0이면 계산만 40~60 ms | rAF로 한 프레임에 한 번만 계산. Mac에서 16 ms를 넘으면 계산을 Web Worker로 옮긴다. 근육 볼륨이 있을 때는 볼륨 0 결과를 키·비율이 같은 동안 재사용하는 캐시가 다음 후보 |
| 처음 받는 데이터 | 남성 0.6.10 5.3 MB(gzip 3.9 MB), 여성 2.1 MB(gzip 1.7 MB) | 체형 더보기를 처음 열 때만 받고 sha256 키로 캐시(30분). 평소 앱 실행에는 영향 없음. BFF는 `immutable` 캐시 헤더 |
| 메모리 | 자산 3.4 MB + 계산 버퍼(정점×3 float64 두 개 ≈ 1.2 MB) + GPU 버퍼 | 박스가 닫히면 캔버스·컨텍스트 해제 |

### 4.2 WebGL 컨텍스트

- 후보 카드는 공유 렌더러 하나로 한 번 그리고 PNG로 바꾼다(`renderCandidate.ts`). 실시간 박스는 **컨텍스트 하나를 따로** 두되 화면에 하나만 존재하게 한다(인물 전환·닫기 시 `dispose`).
- 컨텍스트 손실(`webglcontextlost`) 시 고정 그림으로 떨어지고 다시 열면 재생성.

### 4.3 정확도

- `fold_guard`: 0.6.7·여성은 굽기 단계 조합(프리셋·모든 슬라이더 최소/최대·무작위)에서 한 번도 동작하지 않아 미리보기에서 뺐다. 0.6.10은 근육 볼륨이 있을 때 동작해 앱에 옮겼다. 컨트롤러가 바뀌면 `build_runtime.py`가 `fold_guard_cases`(조합·최대 이동 mm·근육 볼륨)로 다시 보고한다.
- 미리보기는 **중립(T/차렷) 자세만** 그린다. 자세 보정(`AUTO_Pose`, `AUTO_Contact`, 팔 내림 상체 보정)은 포즈별 반복 계산이라 앱에서 하지 않는다 — 포즈를 입힌 결과는 converter가 만든 후보 렌더로 확인한다.
- 골격은 미리보기에 필요 없다(중립 메시만 그림). 단 converter가 같은 `warp`로 본 끝점을 옮기는지 확인해야 미리보기와 FBX가 맞는다.

### 4.4 버전·일관성

- 런타임 자산, 클라이언트 계산 코드, converter가 **같은 `bodyVersion`(남성은 이제 0.6.10 규칙)** 이어야 한다. 헤더의 버전이 다르면 실시간 미리보기를 끄고 고정 그림으로 떨어진다.
- 체형 수치는 서버가 `shapeSha256`으로 저장한다. 미리보기용으로 클라이언트에서 값을 반올림·변형하지 않는다.
- 0.6.0과 0.6.2+는 snapshot 규칙 버전이 다르다. 오래된 저장값을 조용히 새 규칙으로 해석하지 않는다.

### 4.5 기기·환경

- macOS WKWebView, Windows WebView2 모두 WebGL 지원. WebGL이 없거나 실패하면 지금처럼 고정 그림(후보 카드의 PNG 폴백과 같은 방식).
- 저사양에서 계산이 16ms를 넘으면 드래그 중에는 해상도를 낮추고 손을 떼면 원래 해상도로 다시 그린다.

### 4.6 UX

- 내 체형 박스만 움직이고 프리셋 줄은 절대 다시 그리지 않는다(고정 그림, `선택됨` 표시만).
- 키 변화가 보이도록 카메라 기준 높이를 고정한다. 대신 195cm에서 머리가 잘리지 않게 여백을 둔다.
- 저장(0.6초 디바운스)과 미리보기는 분리한다. 미리보기는 즉시, 저장은 손을 뗀 뒤.
- 실서버에서 렌더러가 붙기 전까지는 "수치 미리보기 준비 중" 안내를 유지한다(CLAUDE.md §10).
