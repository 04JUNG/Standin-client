# 포즈 검색 — 실제 분석 정보 로딩 미리보기

승인한 구현은 별도 `codex/pose-search-loading-client` worktree에 정리했다. 현재 구현 확인/검증/서버 연동 범위는 [구현 보고서](POSE_LOADING_IMPLEMENTATION.md)를 따른다. 새 구현 worktree의 미리보기 포트는 1437이며, 아래 1436은 보존된 시안 포트다.

6단계는 러프 확인 / 자세 읽기 / 동작 이해 / 포즈 찾기 / 러프 맞춤 / 후보 정리다. 앱과 바가 같은 `PoseSearchPending`을 사용한다. 공유 서버 계약과 분담은 [POSE_ANALYSIS_PROGRESS_V1.md](POSE_ANALYSIS_PROGRESS_V1.md)를 따른다.

## 로컬 확인

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 1436
# http://127.0.0.1:1436/loading-preview.html
```

DEV 전용 엔트리이며 production parser/component를 사용한다. 01~06 버튼으로 구간 선택, 전체 재생/일시정지, 구 서버, 부분 관절, 여러 인물, refine 모든 outcome, 기록/결과/오류, 360px 바, 라이트/다크를 확인할 수 있다. 검색 API/AI 호출/쿼터 사용이 없고 production 엔트리에 포함되지 않는다.

**미리보기는 예시 데이터 재생이며 실서버 분석 화면이 아니다.** 러프/관절/관측 키워드/조정 좌표는 모션 검수용 fixture다. 후보 PNG는 기존 Standin 로컬 모델 QA 렌더(female-muscle-refine-v0.3.1)에서 가져왔으며 이 러프를 실제 검색한 결과가 아니다. 내 러프를 올리면 예시 관절을 그 위에 덮어쓰지 않고 일반 로딩으로 보여준다.

## 실제 앱의 동작

- multipart/queued/running/preparing은 기존 흐름을 유지한다. 선택적 `progress`를 running에서만 읽는다.
- 원본 러프와 같은 contain/meet 영역에 정규화 좌표를 맞춘다. 가려진 관절은 null이며 얼굴 세부점은 그리지 않는다. 다인원은 실제 유효 관절이 있는 한 인물을 집중해 같은 SVG viewBox에서 원본과 관절을 함께 확대한다. 최종 순서 미정이면 서버 focus를 '인물 분석 중'으로 표시하고 최종 인물 번호와 섞지 않는다.
- 그림을 가리는 '동작 특징' 배지를 제거했다. 실제 키워드가 이미지 주변에서 잠깐 읽힌 뒤 러프 안으로 작아지며 흡수된다. stable id+label이 같은 항목은 단계/sequence 갱신에도 다시 재생하지 않고 새 항목만 재생한다. 컷/시점/인물 수는 optional scene의 실제 관측만 사용하며 이미지 밖 정보 영역에 남긴다. 요약은 아래 텍스트로도 남긴다.
- 실제 후보만 카드로 펼친 뒤 오른쪽에서 들어와 중앙을 지나 왼쪽으로 빠져나가는 한 방향 스트림으로 이어진다. 화면 밖에서만 카드를 재배치하며 진행 방향을 되돌리지 않는다. 카드 복제/추가 이미지 요청은 하지 않는다. 비교 중 후보는 클릭/선택/저장할 수 없다. 최종 rank를 그대로 반영한다.
- 실제 improved 전후만 보간한다. 명시된 activeJoints만 활성 조정 관절로 표시하고 러프 위치가 입력되는 경로를 그린다. activeJoints가 없을 때는 결과의 실제 전후 좌표 차이를 '바뀐 관절 위치'로 구분하며 running 활성 관절을 추측하지 않는다. unchanged/reverted/skipped는 가짜 관절 이동을 만들지 않는다. 기존 선택 후 refine를 자동 실행하지 않는다. 실제 running/improved일 때만 활성/변경된 관절 주변에 작은 반짝임과 얇은 빛 스윕을 더한다. 품질 점수나 성공률로 표시하지 않으며 unchanged/reverted/skipped에서는 강화 효과를 재생하지 않는다.
- 없는/손상된 데이터는 일반 로딩을 유지한다. 최신 snapshot은 순서가 뒤바뀐 polling에 덮어써지지 않는다. 앱/바는 같은 Job cache를 공유한다.
- completed/skipped는 서버가 명시한 값만 표시한다. 단계 순서나 타이머로 완료를 추정하지 않는다.
- 퍼센트는 예상치이며 pending 중 최대 98%. 구 서버에서 실제 snapshot이 늦게 와도 진행률은 뒤로 가지 않는다.
- 결과/실패는 즉시 기존 화면에 마운트한다. 실제 결과가 도착한 경우에만 100%를 표시하고 760ms 위치·크기·투명도 전환로 결과에 이어진다. 820ms 타이머는 시각 레이어 정리만 하며 결과 조회/마운트/선택을 기다리게 하지 않는다. Top5 카드는 36ms 간격으로 조금씩 이어서 들어온다. GPU 합성 가능한 transform/opacity만 사용한다. 기록·캐시 결과·실패·reduced-motion에는 성공 전환을 재생하지 않는다.
- 설치 인증이 필요한 준비 이미지에는 기존 API fetch를 사용한다. 이미지 실패는 분석 실패를 만들지 않는다. 취소/교체 시 blob을 정리한다.
- 기록 조회는 남아 있는 다른 초안과 퍼센트를 노출하지 않는다. reduced-motion에서 키워드/카드 이동과 관절 보간을 멈춘다.

실제 Tauri/Rust/OS 동작과 배포 서버의 분석 품질·단계 제공 여부는 이 DEV 재생으로 검증됐다고 주장하지 않는다.


완료 전환은 `완료 전환 보기` 버튼으로 확인할 수 있다. DEV의 05번은 조정 결과가 '조정됨'일 때 예시 running → improved packet을 재생해 실제 전후 보간/입력 흐름을 보여준다. 이 예시는 현재 서버 `/analyze`가 자동 refine를 실행한다는 뜻이 아니다.

## 04 후보 카드 묶음 디테일 (2026-11-06)

카드 수 5개는 그대로 유지했다. 5장을 함께 fan으로 펼친 뒤 같은 간격의 연속 리본으로 이어진다. 화면 중앙에 한 장씩 머무르던 구간과 비어 있던 이동 구간을 없애, 1280px 앱에서 약 4장, 작은 패널에서도 여러 카드가 동시에 움직인다. 중앙의 미세한 lift/scale/각도/겹침 순서와 Sky 테두리 광택, 카드 묶음을 가로지르는 얇은 빛, 실제 후보 수의 작은 하단 표식으로 디테일을 더했다. 04에서 키워드가 카드 위를 덮지 않도록 이미지 밖 요약만 유지한다.

실제 이미지 노드는 여전히 후보당 하나이며 순서/데이터/API 호출은 바꾸지 않는다. 새 모션은 streaming 후보 카드에만 적용하고 03/05/06 모션을 변경하지 않았다. 관련 컴포넌트 검사 37개, typecheck/build/lint(기존 경고 1건, 오류 없음), 1280px/462px/360px 라이트·다크 브라우저 검수 통과.
