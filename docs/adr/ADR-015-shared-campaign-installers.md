# ADR-015: 공통 소재를 담은 설치 파일

2026-10-31. 승인된 목표: 랜딩의 별도 앱 열기 클릭 없이 새 설치·실행의 소재별 건수 비교.

## 사용자 흐름

v0.2.8부터 production 릴리스는 Windows x64 / macOS Universal 각각 neutral,
meta-poster-a, meta-hook-a를 같은 커밋·버전·앱 identifier로 서명한다. 랜딩은 검증된
UTM에 해당하는 설치 파일을 선택한다. 파일명뿐 아니라 서명된 앱 안의
VITE_INSTALL_CREATIVE에 공통 소재를 포함하므로 파일명 변경이나 Mac의 Applications
복사에 의존하지 않는다. 개인별 코드, 클릭 ID, IP 매칭, 클립보드 조회는 없다.

첫 실행에서 기존 설치 자격증명이 없을 때만 소재를 기기에 최대 7일 보관한다.
자동 업데이트가 neutral 패키지로 교체되기 전에 이 단계가 실행된다. 등록에 성공하면
소재를 한 번 소비하고 v0.2.7의 비식별 건수 경로를 시작한다. 실패한 등록은 소비하지 않는다.
사용/만료 뒤에는 소재·시각 없는 used 표시만 재사용 방지용으로 남으며 전체 데이터 삭제 시
삭제한다. 기존 설치에는 소재를 적용하지 않고 대기 소재도 지운다.

설치 소재가 앱 열기 링크보다 우선한다. 선택 동의가 true인 새 설치에만 기존 설치별
광고 연결 경로에도 동일 소재를 전달한다. 선택 거절 시 설치·작업 ID와 연결하지 않는다.
일반 패키지는 기존 앱 열기 링크를 지원한다. 과거 설치·과거 이용 소급 없음.

## 배포와 검증

동일 릴리스의 소재별 파일 이름은 Standin_VERSION_meta-poster-a_x64-setup.exe,
Standin_VERSION_meta-hook-a_universal.dmg 형태다. 표준 이름의 중립 설치 파일도 유지한다.
모든 빌드의 서명/공증이 성공해야 finalize가 진행하며, 각 소재의 Windows/Universal Mac
패키지 존재 및 neutral updater 피드를 검사한 후에만 공개한다. campaign matrix는
latest.json을 업로드하지 못한다. 업데이터는 모든 사용자에게 neutral 패키지를 제공한다.
staging은 기존 2개 중립 빌드만 만든다. 공개 버전은 덮어쓰지 않는다.

새 소재별 설치 파일·동의 거절·첫 분석 성공은 자동 테스트로 검증한다. 실제 운영에
합성 이벤트를 넣지 않는다. Windows/macOS 서명 빌드와 각 OS의 패키지 실행 확인을
릴리스 검증 기록에 구분해 남긴다.

공유·재설치한 패키지는 배포 소재를 나타낼 뿐 실제 광고 조회/개인 수를 증명하지 않는다.
일반 파일, 오래된 버전, 다른 기기에서 UTM이 사라진 다운로드, 통신 실패는 미분류/누락된다.
등록 후 첫 분석 7일, 전날까지 합계, 5 미만 숨김, 90일 보관 등 서버 계약은 그대로다.
